# SEO architecture (Phase 1)

**Positioning:** Find Your Split. Build Your Workout. Train Smarter. The moat is the loop *Search → split → finder → planner → exercises/muscles → coverage → calculators*, powered by one canonical dataset (`src/data/*`).

## URL architecture
| Section | URL | Notes |
|---|---|---|
| Home | `/` | Org + WebSite JSON-LD |
| Splits hub | `/workout-splits` | compares all splits; links to everything below |
| Day-based | `/workout-splits/{2..7}-day` | data in `src/data/dayPlans.ts`; unique structures, trade-offs, recovery, FAQs per page |
| Split types | `/workout-splits/{push-pull-legs, upper-lower, full-body, bro-split, arnold-split}` | data in `splits.ts` |
| Comparisons | `/workout-splits/{ppl-vs-upper-lower, full-body-vs-upper-lower, ppl-vs-bro-split, arnold-vs-ppl}` | data in `comparisons.ts` |
| Goal-based | `/workout-splits/{for-beginners, for-muscle-gain, for-strength, for-fat-loss, for-busy-schedules}` | data in `goalPlans.ts` |
| Decision page | `/workout-splits/best-workout-split` | explanatory + embedded finder |
| Tool | `/workout-split-finder` | WebApplication JSON-LD |
| Planner | `/workout-planner` | deep links `?split=&days=&add=&cat=` (canonical stays `/workout-planner`) |
| Exercises | `/exercises`, `/exercises/{slug}` | dynamic from `exercises.ts`; quality gate (below) |
| Muscles | `/muscles`, `/muscles/{slug}` | 16 pages, one data-driven route (`muscles.ts`) |
| Calculators | `/calculators`, `/calculators/{tdee,macros,bmi}` | methodology + limitations on each |
| Guides | `/guides`, `/guides/{slug}` | data in `guides.ts` (+ one hand-built guide) |
| Trust | `/about`, `/methodology`, `/methodology/{exercises,workout-splits,calculators}` | no invented credentials |

Old URLs (`/ppl-workout`, `/tools/*`, `/blog`, `/workout-builder`) were removed rather than redirected because the site was not yet live/indexed. **If any old URL has been shared publicly, add 301s in `public/_redirects`.**

## Canonical rules
- No trailing slash (Cloudflare Pages serves `/x/index.html` at `/x`); root is `https://splitsworkout.com/`.
- Query-string states (`?q=`, `?muscle=`, planner deep links) canonicalise to the clean URL. Layout builds canonicals from the `canonical` prop via `cleanPath()`.
- Planner state is client-side (localStorage); user workouts never create URLs, so nothing user-generated can enter the index.

## Indexing quality gate (exercises)
- `src/data/unreviewed-exercises.json` lists exercises not yet reviewed (153 now). All of them are also **hidden** from the library, planner picker, counts and swap suggestions via `hidden-exercises.json` (61 stunts/drills) and `exercise-duplicates.json` (92 near-duplicates mapped to a reviewed exercise). Hidden pages keep their URL and data, render `noindex, follow`, and show a "variation of …" or "specialist movement" notice. They render with `noindex, follow`, are excluded from the sitemap, and remain fully usable in the library and planner.
- **Promote** an exercise: rewrite cues/mistakes/description, add ≥2 alternatives, delete its slug from the JSON. It becomes indexable and enters the sitemap on the next build.
- `node scripts/exercise-quality-report.mjs` shows each exercise's remaining gaps. Current: 178 indexable (all pass), 153 noindex (all hidden; review queue is empty). Visible library = 178 exercises.

## Structured data (only what is visible on the page)
| Page type | JSON-LD |
|---|---|
| Home | Organization, WebSite |
| All non-home pages | BreadcrumbList |
| Split/day/exercise/muscle/guide/methodology/about | Article (publisher = Organization; no dates or authors invented) |
| Planner, Finder, calculators | WebApplication (no ratings/prices) |
FAQ markup was removed: FAQs are visible as content but are not marked up (Google restricts FAQ rich results and the prompt forbids schema as a trick).

## Sitemap / robots
- `src/pages/sitemap.xml.ts` generates the sitemap at build time from the same datasets; noindex exercises are excluded. The audit fails the build check if sitemap and robots meta disagree.
- `public/robots.txt` allows everything and points at the sitemap; noindex is done with meta tags, not robots blocking.

## Social / images
- 6 branded OG images (`public/og/*.png`, generated by `scripts/generate-og.py`): default, splits, exercises, muscles, tools, guides.
- Exercise pages render an inline SVG diagram (`role="img"`, `<title>` and `aria-label` = "{exercise} — start and finish positions"), generated at build time (~4.5 KB each, no extra requests).
- Logo and mascot converted to WebP (~6.6 MB → ~0.7 MB); explicit `width/height` on key images; descriptive alt text.
- Video: no videos exist, so no VideoObject markup. When videos are added, add `VideoObject` per page and reference it from the exercise media manifest.

## Navigation
Header: Workout Splits · Exercises · Muscles · Workout Planner · Calculators · **Find My Split** (CTA). Footer groups: Workout Splits · Tools · Calculators · About (Methodology, Contact, Privacy, Terms).

## Multilingual (future)
Not launched — no thin translations. When a locale ships: add `/{lang}/…` routes, localised titles/descriptions/nav, reciprocal `hreflang` + `x-default`, and enable the `i18n` block already in `astro.config.mjs`. Hreflang is deliberately **not** emitted today.

## Programmatic SEO rules
Only entities with real content get indexable pages (exercises that pass the gate, splits, muscles). No pages for exercise × gender/home/reps/etc. Comparison pages are limited to real search intents (live: PPL vs upper/lower, full body vs upper/lower, PPL vs bro split, Arnold vs PPL).

## Automation
| Script | Purpose |
|---|---|
| `npm run audit:seo` (`scripts/seo-audit.mjs`) | titles, descriptions, H1, canonical, sitemap↔robots consistency, broken links, orphans, JSON-LD validity, breadcrumbs, image alt, thin content, OG files, contextual inbound links. Consolidates the metadata/structured-data/orphan/internal-link/content audits |
| `npm run validate:exercises` (runs as `prebuild`) | duplicate slugs, alternatives, split→exercise, relatedSplits, muscle→exercise refs. **Build fails on bad data** |
| `node scripts/test-swap-engine.mjs` | swap-engine regression test (ranking quality, equipment presets, no unreviewed suggestions, coverage) |
| `node scripts/test-split-engine.mjs` | recommendation-engine regression test (5,832 input combos) |
| `node scripts/exercise-quality-report.mjs` | promotion queue for noindex exercises |
| `npm run og` | regenerate OG images |

## Route design note
`src/pages/workout-splits/[slug].astro` serves day plans, comparisons and goal pages from three datasets via `getStaticPaths` props (`DayPlanView`, `CompareView`, `GoalView` components). Static pages (`push-pull-legs`, `best-workout-split`, …) take precedence over the dynamic route. Slugs must stay unique across the three datasets.
